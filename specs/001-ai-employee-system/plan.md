# Implementation Plan: AI Employee System

**Branch**: `001-ai-employee-system` | **Date**: 2026-02-17 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/001-ai-employee-system/spec.md`

## Summary

Build a local-first autonomous Digital FTE delivered in four tiers.
The system uses Python watchers for event detection, Claude Code
Agent Skills for reasoning, MCP servers for external integrations,
and file-based state (Obsidian vault folders) as its workflow engine.
This plan covers all four implementation phases: Bronze, Silver, Gold,
and Platinum.

## Technical Context

**Language/Version**: Python 3.12
**Primary Dependencies**: watchdog (filesystem), schedule (cron),
  Claude Code SDK (skills), MCP protocol (tool servers)
**Storage**: File-based — Obsidian vault folders with markdown + YAML
  front-matter. JSON for logs and config.
**Testing**: pytest + pytest-mock. Manual integration tests via
  file drops and MCP test harnesses.
**Target Platform**: Linux / macOS / WSL2 (local). Docker for
  potential Platinum cloud deployment.
**Project Type**: Single project (Python package)
**Performance Goals**: Watcher detection < 30s, processing cycle < 5m
  end-to-end, dashboard regeneration < 2s.
**Constraints**: Local-first, no external database, DRY_RUN default,
  all state in vault folders, all AI via Agent Skills.
**Scale/Scope**: Single user, ~50 items/day throughput, 5-10
  concurrent items in pipeline.

## Phase 1: Bronze — Local File Processing Loop

### Dependencies

- Python 3.12
- `watchdog` (filesystem events)
- `pyyaml` (front-matter parsing)
- `python-dotenv` (.env loading)
- Claude Code (for skill execution)

### MCP Servers Required

None (Bronze is fully local).

### Watchers Required

- **Filesystem Watcher** (`src/watchers/filesystem.py`): Uses
  `watchdog` to monitor `/Inbox` for new `.md` files. Waits for
  file stability (2s default). Moves detected files to
  `/Needs_Action` with a triage tag.

### Skills to Implement

1. **Triage Skill** (`src/skills/triage.py`):
   Reads item content, classifies type (file, task, request),
   assigns priority (low/medium/high/urgent), sets
   `requires_approval` flag. Moves item to `/Needs_Action`.

2. **Planning Skill** (`src/skills/planner.py`):
   Reads item from `/Needs_Action`, uses Claude to decompose into
   steps, writes `Plan.md` to `/Plans` with step list, each step
   tagged with approval requirement.

3. **Executor Skill** (`src/skills/executor.py`):
   Reads plans from `/Plans`, executes steps sequentially, updates
   step status in-place. Moves item to `/In_Progress` during
   execution, then to `/Done` on completion or `/Errors` on failure.

4. **Dashboard Skill** (`src/skills/dashboard.py`):
   Counts files per vault folder, lists recent log entries, writes
   `/Dashboard.md` with summary table and last-updated timestamp.

## Phase 4: Platinum — Always-On Cloud + Local Executive

### Dependencies (additions to Gold)

- All Bronze, Silver, and Gold phases complete and stable
- `docker` + `docker-compose` (containerization)
- `rsync` or custom sync daemon (vault sync)
- `cryptography` (TLS/mTLS for cloud-local comms)
- `paramiko` (SSH tunneling for sync, if needed)
- `psutil` (process/system health monitoring)
- `requests` (health check HTTP endpoints)
- Cloud Linux server or VPS (e.g., Hetzner, DigitalOcean, AWS EC2)

### MCP Servers Required (additions to Gold)

None new. Existing MCP servers (Email, Odoo, Social) run on the cloud
instance. A **Credential Proxy** (not MCP) mediates secure access.

### Watchers Required (additions to Gold)

- **Sync Watcher** (`src/watchers/sync.py`): Monitors a local sync
  staging directory for inbound changes from the cloud instance.
  Triggers merge into local vault when new sync payloads arrive.
  Detects conflicts (same item modified on both sides) and flags
  for human resolution.

### Skills to Implement (additions to Gold)

10. **Data Classifier Skill** (`src/skills/data_classifier.py`):
    Reads item content, assigns `classification` tag (`local_only`,
    `syncable`, `redacted_summary`) based on configurable rules
    (FR-053/054). Defaults to `local_only` (fail-safe). Runs
    automatically on every new item before sync eligibility check.

11. **Health Monitor Skill** (`src/skills/health_monitor.py`):
    Polls all components (watchers, MCP servers, sync service) at
    configurable interval (default: 60s). Attempts auto-recovery
    for failed components (restart up to 3x with backoff). Generates
    `/Reports/Health_YYYY-MM-DD_HH.json` hourly. Alerts user within
    5 minutes of unrecoverable failure (FR-055/056/058/059).

12. **Sync Skill** (`src/skills/sync.py`):
    Manages bidirectional vault sync between cloud and local.
    Filters items by `classification` tag — excludes `local_only`,
    sends `syncable` in full, sends `redacted_summary` as redacted
    digest. Handles conflict detection, resumable transfers, and
    sync manifest updates (FR-052/053).

## Cross-Cutting Concerns

### DRY_RUN Mode Implementation

All skills and watchers check `config.DRY_RUN` before any
side-effecting operation:

- **File moves**: `state_machine.move()` logs the intended move but
  does not execute it.
- **MCP calls**: MCP clients return mock success responses.
- **Log entries**: All entries include `"dry_run": true` and
  `[DRY_RUN]` prefix in action string.
- **Dashboard**: Shows `[DRY_RUN MODE]` banner.

### Security Model Implementation

- `.env` loaded once at startup by `config.py`. No credential values
  passed through vault files.
- `logger.py` includes a `redact()` function that masks emails
  (j***@example.com), financial amounts (shown as ranges), and
  personal identifiers.
- `config.py` includes a `credential_leak_check()` that scans any
  file about to be written for .env values and raises an error if
  found (FR-035).

### Error Handling Strategy

- `src/engine/retry.py` provides a `@with_retry` decorator:
  - `base_delay`: 2s (configurable)
  - `max_retries`: 3 (configurable)
  - `multiplier`: 2x
  - On exhaustion: moves item to `/Errors` with full context.
- All MCP calls are wrapped in `@with_retry`.
- Watcher crashes are caught by the main loop, logged, and the
  watcher is restarted (up to 3 times).

### Audit Logging Strategy

- `src/engine/logger.py` writes to `/Logs/YYYY-MM-DD.json`.
- File is opened in append mode (`a`), JSON array is maintained
  by reading existing entries and appending.
- Each log entry follows FR-038 schema exactly.
- `logger.py` validates schema before writing.
